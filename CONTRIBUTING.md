# Contributing

Thanks for helping. Bug reports, missing endpoints and fixes are all welcome.
For larger changes, open an issue first so we can agree on the API.

## Development setup

You need Go 1.26 or newer (CI tests the two latest Go releases) and
[golangci-lint v2](https://golangci-lint.run/docs/welcome/install/).

```sh
git clone https://github.com/koative/hyperliquid-go
cd hyperliquid-go
go test ./...
```

## Checks

Run these before opening a pull request; CI runs the same:

```sh
go test -race -shuffle=on ./...
golangci-lint run ./...
golangci-lint fmt        # gofumpt + goimports
go mod tidy -diff
go run golang.org/x/vuln/cmd/govulncheck@latest ./...
```

Unit tests never touch the network. Fuzz targets run nightly; run one locally
with, for example:

```sh
go test -run='^$' -fuzz='^FuzzFormatPrice$' -fuzztime=1m .
go test -run='^$' -fuzz='^FuzzFromJSON$' -fuzztime=1m ./internal/msgpack
```

## Code conventions

- Every exported identifier has a doc comment that starts with its name.
- Prices, sizes and amounts are `Decimal`, never `float64`.
- Action struct field order and JSON tags are the signed bytes: they must
  match the wire order of the Hyperliquid API exactly.
- New exchange actions need proof the signature is right: a golden vector
  from the official Python SDK, or a Testnet submission whose error message
  names the signer's address.

## Signing vectors

`testdata/signing_vectors.json` is generated by the official
[Python SDK](https://github.com/hyperliquid-dex/hyperliquid-python-sdk), and
the Go tests check that signatures match it byte for byte. To add or refresh
vectors, edit `testdata/gen_signing_vectors.py` and regenerate:

```sh
python3 -m venv .venv
.venv/bin/pip install hyperliquid-python-sdk
.venv/bin/python testdata/gen_signing_vectors.py > testdata/signing_vectors.json
go test -run 'MatchesPython' .
```

## Pull requests

Pull requests are squash-merged, and the PR title becomes the commit message.
Titles must follow [Conventional Commits](https://www.conventionalcommits.org/)
because [release-please](https://github.com/googleapis/release-please) builds
the changelog and the next version from them:

- `feat: add vaultTransfer action` → new minor version
- `fix: decode null cloid in userFills` → new patch version
- `feat!: rename OrderResult fields` → breaking change (minor version while in v0)
- `docs:`, `test:`, `refactor:`, `chore:`, `ci:` → no release
